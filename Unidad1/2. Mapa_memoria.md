# Introducción

Un mapa de memoria de un microprocesador o microcontrolador es una representación completa de todas las direcciones que la unidad de control de la CPU puede generar para acceder a diferentes tipos de memoria y periféricos. Este mapa incluye tanto la memoria RAM (Memoria de Acceso Aleatorio) como la ROM (Memoria de Solo Lectura), así como cualquier otro dispositivo periférico conectado al sistema.

El mapa de memoria está directamente relacionado con el Bus de Direcciones del procesador. Este bus es un conjunto de líneas de comunicación que la CPU utiliza para enviar las direcciones de memoria. Cada línea del bus de direcciones representa un bit en la dirección de memoria. Por ejemplo, en la figura 1, se ilustra un bus de direcciones que va desde A0 hasta A15, lo que indica que el procesador puede generar direcciones de 16 bits.

Figura 2. *Pinout* del microprocesador MC 6808

Este bus de direcciones de 16 bits permite al procesador acceder a un espacio de direcciones total de $2^{16} = 65536$ ubicaciones de memoria diferentes. Dependiendo de cómo se diseñe el sistema, estas ubicaciones pueden estar asignadas a diferentes tipos de memoria y periféricos. Por ejemplo, las primeras direcciones pueden estar reservadas para la memoria ROM, donde se almacena el código del programa, mientras que otras direcciones pueden estar asignadas a la memoria RAM, donde se almacenan datos temporales y variables. Además, algunas direcciones pueden estar mapeadas a registros de control y datos de periféricos como puertos de entrada/salida, temporizadores, y otros dispositivos.

El diseño del mapa de memoria es crucial para el funcionamiento eficiente del microprocesador o microcontrolador, ya que determina cómo y dónde se accede a la memoria y a los periféricos durante la operación del sistema.

En general, el microprocesador **MC6802**, que pertenece a la familia de microcomputadoras **M6800**, utiliza un bus de direcciones de 16 bits (A0…A15), lo que permite acceder a un espacio de memoria total de 65536 unidades de 8 bits cada una. # Microprocesador familia 8086

Ahora analicemos el caso particular del microprocesador de la familia 8086. En la figura 4, se observa el diagrama de bloques y el *pinout*. 

El mapa de memoria del procesador 8086 de Intel está conformado por un espacio de direcciones de 20 bits (A0…A19), lo que permite acceder a un total de  1 MB (1024K unidades) de memoria. Cada una de estas unidades es de 16 bits, permitiendo una amplia capacidad de almacenamiento y manipulación de datos.

En el 8086, las líneas de datos (D0…D7) y las líneas de direcciones (A0…A15) comparten los mismos pines, utilizando un bus de direcciones y datos multiplexado. Esto significa que las mismas conexiones físicas se utilizan para transmitir tanto las direcciones como los datos, lo cual es una característica diseñada para reducir la cantidad de pines necesarios y simplificar el diseño del chip y del sistema en general.

Para separar las direcciones de los datos durante la operación, el procesador emplea la señal de ALE (Address Latch Enable). Esta señal indica cuándo las líneas están transmitiendo una dirección, permitiendo que un *latch* externo capture y mantenga la dirección mientras las líneas se reutilizan para transferir datos. Este mecanismo asegura que las direcciones y los datos no se mezclen y que cada tipo de información se procese en el momento adecuado.

Esta organización del bus de direcciones y datos multiplexado en el 8086 facilita la conexión de múltiples dispositivos y módulos de memoria, optimizando el uso de los recursos del sistema y permitiendo una arquitectura más eficiente y flexible.

Otra perspectiva del espacio de memoria del 8086/88 es como 16 bloques de 64 KB que comienzan en la dirección hexadecimal 000000h y terminan en la dirección 0FFFFFh. Esta división en bloques de 64 KB es una elección arbitraria pero conveniente. Esto se debe a que el dígito hexadecimal más significativo incrementa en 1 con cada bloque adicional. Es decir, la dirección 20000h está 65,536 bytes más arriba en la memoria que la dirección 10000h. Note que se requieren cinco dígitos hexadecimales para representar una dirección de memoria, es decir, 20 bytes.

### Arquitectura de Von Neumann

En la arquitectura de Von Neumann, también conocida como arquitectura de almacenamiento de programas, tanto los datos como las instrucciones se almacenan en la misma memoria y se accede a ellos a través del mismo bus. Esto significa que el mapa de memoria es un espacio unificado que contiene tanto las instrucciones del programa como los datos manipulados por esas instrucciones. Un ejemplo clásico de esta arquitectura es el procesador Intel 8086 (**Ver figura 5**), que utiliza un bus de direcciones de 20 bits, permitiendo acceder a 1 MB de memoria, compartido tanto para el código como para los datos. Observa un diagrama esquemático de esta arquitectura en la figura 6.

### Arquitectura de Harvard

Por otro lado, la arquitectura Harvard tiene una separación clara entre la memoria de instrucciones y la memoria de datos. Observa un esquemático general en la figura 7. 

![Figura 7. Diagrama esquemático de la arquitectura Harvard](https://prod-files-secure.s3.us-west-2.amazonaws.com/86ff57e3-0a96-46be-a958-59ebefbb5e94/72a394ca-67b5-420a-a98e-1315f3d481bb/Harvard_architecture.svg.png)

Esto implica que las instrucciones y los datos se almacenan en memorias diferentes y se accede a ellas a través de buses separados. Un ejemplo de un procesador basado en la arquitectura de Harvard es el microcontrolador PIC16F877 de Microchip (**ver figura 8**), que tiene memoria de programa separada (FLASH) y memoria de datos (RAM). Esta separación permite un acceso simultáneo a instrucciones y datos, lo que puede aumentar la eficiencia y la velocidad de procesamiento.

### Ejemplo Comparativo

En un sistema basado en la arquitectura de Von Neumann, como el **Intel 8086**, el mapa de memoria podría estar configurado de manera que las primeras direcciones contienen el código del programa (por ejemplo, desde 00000h hasta 1FFFFh) y las siguientes direcciones contienen los datos (por ejemplo, desde 20000h hasta 2FFFFh). En cambio, en un sistema basado en la arquitectura de Harvard, como el **PIC16F877**, habría dos mapas de memoria separados: uno para las instrucciones del programa, que podría ir desde 0000h hasta 1FFFh, y otro para los datos, que podría ir desde 0000h hasta 00FFh.

# Clasificación de los procesadores según la complejidad de su repertorio de instrucciones

El funcionamiento del procesador depende de su capacidad para procesar instrucciones. Esta capacidad está en la unidad de decodificación de la instrucción. El tamaño de la unidad, el consumo de energía y la complejidad del set de instrucciones, entre otros, definen la construcción general del procesador (térmicos, mm² de silicio, velocidad, etc.). Las instrucciones nuevas requerían más bits para escribirse. El set de instrucciones es como el vocabulario: mientras más instrucciones tenga, se puede describir con menos palabras y con más precisión cualquier cosa. Sin embargo, el aprendizaje es mayor y se necesita más espacio para dicho conocimiento (diccionario). Algo que benefició este proceso es la capacidad de reducir el tamaño de los transistores desde 1000 nm a los actuales 3 nm (2024). Pero este progreso en los últimos años ha sido muy lento.

## Arquitecturas SISC y RISC

### Arquitectura CISC (Complex Instruction Set Computer)

La arquitectura CISC está diseñada para minimizar la cantidad de instrucciones por programa, sacrificando el número de ciclos de reloj por instrucción. Las instrucciones en CISC son complejas y pueden realizar múltiples operaciones de bajo nivel (como la carga de memoria, una operación aritmética y el almacenamiento de resultado) dentro de una sola instrucción.

**Características:**

- **Instrucciones Complejas:** Pueden realizar múltiples tareas.
- **Decodificación Lenta:** Debido a la complejidad de las instrucciones, la decodificación es más lenta.
- **Tamaño de Instrucción Variable:** Las instrucciones pueden tener diferentes longitudes.
- **Uso de Microprogramación:** Utiliza microcódigo para implementar instrucciones complejas.
- **Ejemplo:** x86 (Intel y AMD).

### Arquitectura RISC (Reduced Instruction Set Computer)

La arquitectura RISC, por otro lado, se enfoca en simplificar las instrucciones, permitiendo que cada instrucción realice una sola operación de bajo nivel y se ejecute en un único ciclo de reloj. Esto permite una mayor velocidad de procesamiento y una mayor eficiencia.

**Características:**

- **Instrucciones Simples:** Realizan una única tarea.
- **Decodificación Rápida:** Las instrucciones simples permiten una decodificación más rápida.
- **Tamaño de Instrucción Fijo:** Las instrucciones tienen un tamaño fijo, generalmente de 4 bytes.
- **Pipeline:** Facilita la implementación de pipelines de instrucción.
- **Ejemplo:** ARM, MIPS.

**Comparación entre SISC y RISC:**

| Característica | CISC (x86) | RISC (ARM, MIPS) |
| --- | --- | --- |
| **Instrucciones** | Complejas y variables en tamaño | Simples y de tamaño fijo |
| **Decodificación** | Más lenta debido a la complejidad | Más rápida debido a la simplicidad |
| **Ejemplo de Instrucción** | `ADD AX, BX` | `ADD R0, R1, R2` (ARM), 
`ADD $t0, $t1, $t2` (MIPS) |
| **Tamaño de Instrucción** | Variable (1 a 6 bytes) | Fijo (4 bytes) |
| **Ciclos de Reloj** | 1-3 ciclos, puede variar según la instrucción | 1 ciclo por instrucción |
| **Microprogramación** | Utiliza microcódigo para instrucciones complejas | No utiliza microcódigo, instrucciones en hardware |
| **Pipeline** | Menos eficiente debido a instrucciones variables | Muy eficiente, diseño optimizado para pipelining |

<aside>
💡

La elección entre CISC y RISC depende de los objetivos específicos del diseño del procesador y de las aplicaciones que se espera que maneje. CISC puede ser beneficioso para aplicaciones que requieren instrucciones complejas y un menor número de ciclos de reloj por programa, mientras que RISC es ideal para aplicaciones que se benefician de una alta velocidad de procesamiento y eficiencia energética.

</aside>
