# Instruction Set Architecture - ARM Cortex-M

Para diseñar la Instruction Set Architecture (ISA) en microcontroladores ARM Cortex-M, se deben tener en cuenta las siguientes consideraciones basadas en las ideas proporcionadas:

1. **Obtención de los Datos**:
    - **Registros**: Los microcontroladores ARM Cortex-M poseen un conjunto de registros que se utilizan para almacenar datos temporales y variables. Los registros son esenciales para operaciones rápidas y eficientes, ya que el acceso a los registros es mucho más rápido que el acceso a la memoria principal.
    - **Memoria**: La memoria se utiliza para almacenar tanto el código del programa como los datos. En los microcontroladores ARM Cortex-M, la memoria puede estar dividida en memoria de programa (flash) y memoria de datos (RAM).
    - **Dispositivos de Entrada/Salida**: Los datos también pueden provenir de dispositivos periféricos conectados al microcontrolador, como sensores, actuadores y interfaces de comunicación. Los microcontroladores ARM Cortex-M suelen incluir módulos de entrada/salida para manejar estas interacciones.
2. **Manipulación de los Datos**:
    - **Instrucciones en Lenguaje Ensamblador**: La ISA define un conjunto de instrucciones en lenguaje ensamblador que permiten manipular los datos. Estas instrucciones incluyen operaciones aritméticas, lógicas, de control de flujo y de transferencia de datos. Las instrucciones en lenguaje ensamblador son traducidas a código máquina que puede ser ejecutado directamente por el procesador.
    - **Acciones del Procesador (*Exceptions*)**: El procesador debe ser capaz de manejar eventos inesperados o excepciones durante la ejecución del programa. Las excepciones pueden ser causadas por errores en el código, interrupciones de hardware, o condiciones especiales que requieren atención inmediata del procesador. Los microcontroladores ARM Cortex-M tienen un controlador de excepciones integrado que gestiona estas situaciones de manera eficiente.

# Registros

Los registros son componentes críticos en los microcontroladores ARM Cortex-M, ya que proporcionan almacenamiento rápido y accesible para datos temporales y variables, permitiendo operaciones eficientes y veloces en el procesador. En estos microcontroladores, los registros están divididos en tres categorías principales: 8 registros bajos (R0-R7), 5 registros altos (R8-R12), y 3 registros especiales (R13-R15). Los registros bajos son utilizados generalmente para operaciones frecuentes y de uso general, proporcionando flexibilidad en la ejecución de instrucciones básicas. Los registros altos también son de uso general, pero su uso está más enfocado en operaciones que requieren un manejo más complejo de datos, como en rutinas de interrupción o subrutinas. Por último, los registros especiales tienen funciones específicas: R13 es el puntero de pila (SP), que maneja el contexto de la pila; R14 es el registro de enlace (LR), que guarda la dirección de retorno para subrutinas; y R15 es el contador de programa (PC), que mantiene la dirección de la siguiente instrucción a ejecutar. Esta división optimiza la estructura y el rendimiento del procesador, permitiendo una gestión eficiente y ordenada de las tareas.

# Mapa de memoria

A continuación se muestra el mapa de memoria de la arquitectura. Comienza con la memoria de código, que incluye la memoria flash donde se almacena el firmware del dispositivo. A continuación, se encuentra la memoria de datos, que generalmente es la RAM utilizada para almacenar variables y datos temporales en tiempo de ejecución. Luego, están los periféricos, que contienen registros de control y estado para interactuar con dispositivos externos como sensores y actuadores. Además, existe una región dedicada a la memoria de sistema, que incluye áreas para el System Control Space (SCS) y los controladores de interrupciones. Esta organización facilita un acceso rápido y eficiente a diferentes tipos de memoria y periféricos, optimizando el rendimiento del microcontrolador.

# Compatibilidad entre set de instrucciones

En un programa de **assembly** para un microcontrolador **ARM Cortex-M4**, la instrucción:

```
.syntax unified
```

se usa para indicar que el código ensamblador debe seguir la **sintaxis unificada de ARM**. Esto es necesario porque ARM tiene dos conjuntos de instrucciones:

1. **ARM (A32)**: Instrucciones de 32 bits.
2. **Thumb (T32)**: Un conjunto reducido de instrucciones de 16 y 32 bits más eficiente en espacio.

El **Cortex-M4** utiliza el **modo Thumb-2**, que combina instrucciones de 16 y 32 bits para mejorar la eficiencia sin perder flexibilidad. La sintaxis unificada permite escribir código ensamblador que es compatible tanto con instrucciones ARM como Thumb sin necesidad de cambiar entre diferentes modos de ensamblador.

### Beneficios de `.syntax unified`

- **Consistencia**: Permite escribir código que se compila correctamente en **Thumb-2** sin ambigüedades.
- **Compatibilidad**: Evita errores de sintaxis cuando se usa ensamblador en combinación con C en herramientas como **GCC** y **Keil**.
- **Facilidad de lectura**: Usa una sintaxis uniforme para todas las instrucciones, en lugar de depender de diferencias entre modos.

Si no se usa `.syntax unified`, algunas instrucciones pueden no ensamblarse correctamente o generar advertencias en compiladores modernos.

### Ejemplo de Código

```
.syntax unified
.cpu cortex-m4
.thumb

.global main
main:
    MOV R0, #1     @ Mueve el valor 1 a R0
    BX LR          @ Regresa de la función
```

_start:

1. **Inicialización de registros**:
    - `MOV R0, #0x20000000`: Asigna la dirección base de la memoria a R0.
    - `MOV R1, #0x12345678`: Asigna un valor de 32 bits a R1.
    - `MOV R2, #0xFF`: Asigna un valor de 8 bits a R2.
    - `MOV R3, #0x1234`: Asigna un valor de 16 bits a R3.
2. **Instrucciones de Almacenamiento (Store)**:
    - `STR R1, [R0]`: Almacena el valor de R1 en la dirección apuntada por R0 (32 bits).
    - `STRB R2, [R0, #4]`: Almacena el valor de R2 en la dirección (R0 + 4) (8 bits).
    - `STRH R3, [R0, #6]`: Almacena el valor de R3 en la dirección (R0 + 6) (16 bits).
3. **Instrucciones de Carga (Load)**:
    - `LDR R4, [R0]`: Carga un valor de 32 bits desde la dirección apuntada por R0 a R4.
    - `LDRB R5, [R0, #4]`: Carga un valor de 8 bits desde la dirección (R0 + 4) a R5.
    - `LDRH R6, [R0, #6]`: Carga un valor de 16 bits desde la dirección (R0 + 6) a R6.
4. **Pre-desplazamiento y Post-desplazamiento**:
    - `STR R1, [R0, #8]!`: Almacena R1 en (R0 + 8) y actualiza R0 a (R0 + 8).
    - `LDR R7, [R0], #4`: Carga en R7 el valor en la dirección actual de R0 y luego incrementa R0 en 4.
5. **Uso de Registros de Índice**:
    - `MOV R8, #2`: Asigna el valor 2 a R8.
    - `STR R2, [R0, R8]`: Almacena R2 en la dirección (R0 + R8).
    - `LDR R9, [R0, R8]`: Carga en R9 el valor en la dirección (R0 + R8).

## Direccionamiento Literal

En el siguiente ejemplo se muestra la manera de realizar direccionamiento literal, para ello se utiliza la instrucción `.equ` para definir una constante y luego utilizarla en un programa.

```nasm
.syntax unified
.global _start
.text

// Definición de constantes usando .equ
.equ BASE_ADDRESS, 0x20000000
.equ VALUE1, 10
.equ VALUE2, 20

_start:
    // Inicialización de registros usando las constantes definidas
    LDR R0, =BASE_ADDRESS   // R0 = Dirección base de la memoria
    MOV R1, #VALUE1         // R1 = 10
    MOV R2, #VALUE2         // R2 = 20

    // Operaciones Aritméticas usando las constantes
    ADD R3, R1, R2          // R3 = R1 + R2 -> R3 = 10 + 20 = 30
    SUB R4, R2, R1          // R4 = R2 - R1 -> R4 = 20 - 10 = 10

    // Almacenar los resultados en memoria
    STR R3, [R0]            // Almacena R3 en la dirección BASE_ADDRESS
    STR R4, [R0, #4]        // Almacena R4 en la dirección BASE_ADDRESS + 4

    // Cargar los resultados desde la memoria para verificar
    LDR R5, [R0]            // Carga en R5 el valor almacenado en BASE_ADDRESS (resultado de la suma)
    LDR R6, [R0, #4]        // Carga en R6 el valor almacenado en BASE_ADDRESS + 4 (resultado de la resta)

    // Bucle infinito para detener la ejecución
    B .

.end
```

### Explicación del Código

1. **Definición de Constantes**:
    - `.equ BASE_ADDRESS, 0x20000000`: Define la constante `BASE_ADDRESS` con el valor `0x20000000`.
    - `.equ VALUE1, 10`: Define la constante `VALUE1` con el valor `10`.
    - `.equ VALUE2, 20`: Define la constante `VALUE2` con el valor `20`.
2. **Inicialización de Registros**:
    - `LDR R0, =BASE_ADDRESS`: Carga la dirección base `0x20000000` en `R0` usando "Literal Addressing".
    - `MOV R1, #VALUE1`: Carga el valor `10` en `R1` usando la constante `VALUE1`.
    - `MOV R2, #VALUE2`: Carga el valor `20` en `R2` usando la constante `VALUE2`.
3. **Operaciones Aritméticas**:
    - `ADD R3, R1, R2`: Suma los valores de `R1` y `R2`, y almacena el resultado en `R3` (`R3 = 30`).
    - `SUB R4, R2, R1`: Resta el valor de `R1` de `R2`, y almacena el resultado en `R4` (`R4 = 10`).
4. **Almacenamiento de Resultados en Memoria**:
    - `STR R3, [R0]`: Almacena el valor de `R3` en la dirección `BASE_ADDRESS`.
    - `STR R4, [R0, #4]`: Almacena el valor de `R4` en la dirección `BASE_ADDRESS + 4`.
5. **Carga de Resultados desde Memoria**:
    - `LDR R5, [R0]`: Carga en `R5` el valor almacenado en `BASE_ADDRESS` (resultado de la suma).
    - `LDR R6, [R0, #4]`: Carga en `R6` el valor almacenado en `BASE_ADDRESS + 4` (resultado de la resta).
6. **Bucle Infinito**:
    - `B .`: Crea un bucle infinito para detener la ejecución del programa.

## Resumen

- La arquitectura ARM Cortex-M se basa en gran medida en operaciones de carga y almacenamiento (load/store) para mover datos entre registros y la memoria. Estas instrucciones utilizan registros como punteros, lo que permite una manipulación eficiente y directa de direcciones de memoria.
- En este contexto, los valores literales juegan un papel crucial. Son constantes de 32 bits que se definen dentro del código y se sitúan entre segmentos de código ejecutable. Estos valores se acceden mediante un offset del registro del contador de programa (PC), lo que facilita su referencia y uso durante la ejecución del programa. Este enfoque permite una gestión eficiente de constantes y mejora la claridad y mantenimiento del código ensamblador.
- La arquitectura Cortex-M combina operaciones de carga y almacenamiento con el uso de valores literales y registros como punteros, proporcionando una estructura eficiente y flexible para la manipulación de datos y la ejecución de programas.

## Operaciones a nivel de bits

Analiza el siguiente ejemplo. Podrás observar la manera de forzar algunos bits a que se conviertan en unos o ceros. Esto suele ser muy útil cuando se trata de configurar registros de un microcontrolador. El profesor te mostrará ejemplos con las copuertas lógicas para complementar este ejemplo. 

```nasm

.syntax unified
.global _start
.text

// Definición de constantes para las máscaras
.equ MASK_AND, 0x0F0F    // Máscara para la operación AND
.equ MASK_OR, 0x00FF     // Máscara para la operación OR
.equ MASK_XOR, 0x0FF0    // Máscara para la operación XOR
.equ MASK_BIC, 0xF00F    // Máscara para la operación BIC

_start:
// Inicialización de registros con valores de ejemplo
MOV R0, #0xF0F0       // R0 = 1111000011110000 en binario

// Operación AND para forzar bits a cero
MOV R1, #MASK_AND     // R1 = 0000111100001111 en binario
AND R2, R0, R1        // R2 = R0 AND R1, resultado: 0000000000000000

// Operación OR para forzar bits a uno
MOV R3, #MASK_OR      // R3 = 0000000011111111 en binario
ORR R4, R0, R3        // R4 = R0 OR R3, resultado: 1111000011111111

// Operación XOR para invertir bits específicos
MOV R5, #MASK_XOR     // R5 = 0000111111110000 en binario
EOR R6, R0, R5        // R6 = R0 XOR R5, resultado: 1111111100000000

// Operación NOT para complementar bits
MVN R7, R0            // R7 = NOT R0, resultado: 0000111100001111

// Operación BIC para borrar bits específicos
MOV R8, #MASK_BIC     // R8 = 1111000000001111 en binario
BIC R9, R0, R8        // R9 = R0 BIC R8, resultado: 0000000011110000

// Bucle infinito para detener la ejecución
B .
.end
```

## Resumen

- La máscara se construye con un 1 en los bits que se van a modificar
- Usar la instrucción ORR para forzar un bit a 1
- Usar la instrucción BIC (MVN-AND) para forzar un bit a 0
- Usar la instrucción EOR para conmutar un bit

## Saltos y condicionales

### Ejemplo de Código en Assembly con Instrucciones de Salto y Condicionales

```nasm
.syntax unified
.global _start
.text

_start:
    MOV R0, #10        // R0 = 10
    MOV R1, #20        // R1 = 20
    CMP R0, R1         // Compara R0 con R1

    BGT label_greater  // Si R0 > R1, salta a label_greater
    BLT label_lesser   // Si R0 < R1, salta a label_lesser
    BEQ label_equal    // Si R0 == R1, salta a label_equal

label_greater:
    MOV R2, #1         // R2 = 1 (indica R0 > R1)
    B end              // Salta a la etiqueta end

label_lesser:
    MOV R2, #2         // R2 = 2 (indica R0 < R1)
    B end              // Salta a la etiqueta end

label_equal:
    MOV R2, #3         // R2 = 3 (indica R0 == R1)

end:
    // Bucle infinito para detener la ejecución
    B .

.end

```

### Tabla de Instrucciones de Salto y Condicionales

| Instrucción | Significado | Descripción |
| --- | --- | --- |
| B | Branch | Salta incondicionalmente a una etiqueta |
| BL | Branch with Link | Salta a una subrutina y guarda la dirección de retorno |
| BX | Branch and Exchange | Salta a una dirección y cambia el estado del procesador |
| BEQ | Branch if Equal | Salta si el resultado de la comparación es igual (Z=1) |
| BNE | Branch if Not Equal | Salta si el resultado de la comparación no es igual (Z=0) |
| BGT | Branch if Greater Than | Salta si mayor (N=V y Z=0) |
| BGE | Branch if Greater Than or Equal | Salta si mayor o igual (N=V) |
| BLT | Branch if Less Than | Salta si menor (N≠V) |
| BLE | Branch if Less Than or Equal | Salta si menor o igual (Z=1 o N≠V) |
| BMI | Branch if Minus | Salta si negativo (N=1) |
| BPL | Branch if Plus | Salta si positivo o cero (N=0) |
| BHI | Branch if Higher | Salta si mayor sin signo (C=1 y Z=0) |
| BLS | Branch if Lower or Same | Salta si menor o igual sin signo (C=0 o Z=1) |
| BVC | Branch if Overflow Clear | Salta si no hay desbordamiento (V=0) |
| BVS | Branch if Overflow Set | Salta si hay desbordamiento (V=1) |
