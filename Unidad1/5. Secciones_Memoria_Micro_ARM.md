# **Actividad 4: Secciones de Memoria en un Microcontrolador ARM Cortex-M4**

## **1. Introducción**

En un microcontrolador ARM Cortex-M4, la memoria se divide en diferentes secciones para organizar de manera eficiente los datos y el código. Estas secciones incluyen la memoria de programa (Flash), la memoria de datos (RAM) y áreas especiales para el almacenamiento de constantes, listas y tablas.

En este tutorial se explicará cada una de estas secciones con ejemplos prácticos y preguntas de control para reforzar el aprendizaje.

---

## **2. Secciones de Memoria**

### **2.1. Sección de Código (Text Segment)**

Esta sección contiene el código del programa almacenado en memoria Flash. Aquí se ubican las instrucciones que ejecuta el procesador.

### **Funcionamiento de los Comandos:**

- `.section .text`: Indica que el contenido pertenece a la sección de código.
- `.global _start`: Declara `_start` como símbolo global y punto de entrada.
- `LDR R0, =mensaje`: Carga la dirección de la etiqueta `mensaje` en el registro `R0`.
- `BL imprimir_mensaje`: Llama a la subrutina `imprimir_mensaje`.
- `BX LR`: Retorna de la función actual.
- `.asciz "Hola Mundo"`: Define una cadena de caracteres terminada en `NULL`.

### **Ejemplo:**

```nasm
    .section .text
    .global _start

_start:
    LDR R0, =mensaje      @ Cargar la dirección de mensaje en R0
    BL imprimir_mensaje   @ Llamar a la función para imprimir mensaje
    loop:
    B loop             @ Bucle infinito

imprimir_mensaje:
    MOV R1, R0           @ Mover la dirección del mensaje a R1
    @ Aquí se implementaría una rutina de impresión en un sistema embebido
    BX LR                @ Retornar

mensaje:
    .asciz "Hola Mundo"
```

- ¿Por qué el código del programa se almacena en la memoria Flash y no en la RAM?

### **2.2. Sección de BSS (Block Started by Symbol)**

La sección BSS almacena variables no inicializadas que se crean en tiempo de ejecución, lo que reduce el uso de memoria Flash, pero es necesario reservar suficiente espacio en RAM al iniciar el programa en la memoria Flash, sino que se asignan en la RAM cuando el programa inicia.

### **Funcionamiento de los Comandos:**

- `.section .bss`: Indica que el contenido pertenece a la sección de datos no inicializados.
- `.lcomm buffer, 64`: Reserva 64 bytes para un buffer sin inicializar.

### **Ejemplo:**

```nasm
    .section .bss
    .lcomm buffer, 64  @ Reserva 64 bytes de memoria en la sección BSS
```

### **Pregunta de Control:**

### **2.4. Tablas y Listas en Memoria**

En un microcontrolador, se pueden almacenar estructuras de datos (como tablas y listas) en la sección de datos para facilitar su acceso.

### **Funcionamiento de los Comandos:**

- `.word`: Almacena valores de 32 bits en memoria consecutivamente.

### **Ejemplo:**

```nasm
lista:
```

## **3. Copia de Datos Entre Memoria y Registros**

Para mover datos entre la memoria y los registros se usan, principalmente, las instrucciones `LDR` (Load) y `STR` (Store).

### **Funcionamiento de los Comandos:**

- `LDR R1, =valor`: Carga la dirección de `valor` en el registro `R1`.
- `LDR R2, [R1]`: Carga el dato apuntado por `R1` en `R2`.
- `STR R2, [R1]`: Almacena el contenido de `R2` en la dirección apuntada por `R1`.

### **Ejemplo:**

```nasm
    LDR R1, =valor   @ Cargar la dirección de valor en R1
    LDR R2, [R1]     @ Cargar el valor de memoria a R2
    STR R2, [R1]     @ Guardar R2 de vuelta en la dirección de R1
```

### **Pregunta de Control:**

- ¿Cuál es la diferencia principal entre `LDR` y `STR`? (Spoiler: `LDR` transfiere datos desde la memoria a un registro, mientras que `STR` transfiere datos desde un registro a la memoria. Por ejemplo, `LDR R2, [R1]` carga en `R2` el valor que se encuentra en la dirección almacenada en `R1`, mientras que `STR R2, [R1]` almacena el contenido de `R2` en la dirección apuntada por `R1`.)

## **4. Ejemplo Final: Almacenar una Imagen para una Matriz de LEDs 8x8**

Las imágenes pueden representarse como un arreglo de bytes, donde cada bit determina el estado (encendido/apagado) de un LED.

### **Funcionamiento de los Comandos:**

- `.byte`: Almacena un valor de 8 bits en memoria.

### **Ejemplo: Imagen de un cuadrado 8x8**

> Nota sobre mapeo de bits: Cada byte define una fila (o columna) de la matriz, y cada bit dentro del byte corresponde a un LED específico. Cuando el bit es 1, el LED se enciende; cuando es 0, se apaga. Esto permite controlar individualmente los 64 LEDs de la matriz.
> 

```nasm
imagen:
    .byte 0b00011000
    .byte 0b00011000
    .byte 0b00011000
    .byte 0b00011000
    .byte 0b00011000
    .byte 0b00011000
    .byte 0b00011000
    .byte 0b00011000
```

### **Pregunta de Control:**

- ¿Cómo podría enviarse este arreglo de bytes a una matriz de LEDs 8x8 para visualizar la imagen?

Por ejemplo, se puede iterar sobre una lista con un bucle en ensamblador:

```nasm
    LDR R0, =lista         @ Cargar la dirección base de la lista
    MOV R1, #0             @ Índice inicial
loop_list:
    LDR R2, [R0, R1, LSL #2]  @ Cargar elemento (R1) de la lista
    ; Aquí se procesaría el valor de R2
    ADD R1, R1, #1
    CMP R1, #5            @ Comparar índice con 5 (longitud de la lista)
    BLT loop_list         @ Si R1 < 5, continuar
```
